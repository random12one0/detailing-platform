Andrew's standing instruction not to do.

**Why the credential-free gates still say nothing about this:** they measure
token PAIRS, and a pair does not know which surface a label lands on. That is
the whole reason `contrast-insitu.mjs` exists and why it is the instrument for
this item.

## THE INSTRUMENT HAD ONLY EVER ASKED ENGLISH

**It walked 32 combinations, every one of them English**, for an item whose
audits both said "everywhere". Widened to both languages this session — and
widening it produced three findings, all of them about the check.

**1 · THE LANGUAGE PASS HAD TO PROVE IT HAPPENED, AND THE FIRST VERSION DID
NOT.** `localeStore.js` stamps the rendered locale on `<html lang>`, so every
target now records what it actually rendered and a pass that fell back is a
FAILURE. Without that the run said *64 combinations, both languages, all
clean* — and **eight of those sixty-four were English measured twice.** It is
the same fault `calendar-legible.mjs` shipped and caught the same night: **no
coverage at all, wearing the look of double.**

**2 · TWO LOCALE KEYS, NOT ONE.** The dashboard reads `dp.lang.app`; the public
pages read `dp.lang`. Setting one switches five screens and leaves three in
English. Both are set now, **as plain strings** — `localeStore.js` stores the
bare locale, so writing JSON leaves it unrecognised and the page silently falls
back.

**3 · THE LANDING AND PRICING PAGES HAVE NO SECOND LANGUAGE AT ALL.** The guard
reported them rendering `lang="en"` through the Spanish pass; `?lang=es` did
not move them either. **`LandingPage.jsx` and `PricingPage.jsx` carry no `t()`
and no i18n import** — they are English-only by design, and `es.js` is the
booking side's catalogue. So the Spanish pass **skips them by declaration**
rather than measuring English twice and calling it Spanish coverage. The
declared target count carries the asymmetry: `4 widths × ((5 tabs + 1 bilingual
public page) × 2 languages + 2 English-only pages)` = **56**.

**And the tab bar is walked by POSITION now, labelled by the English name.**
The first version filtered tabs by their English words, so the Spanish pass
matched nothing — the bar reads «Hoy», «Calendario», «Dinero» — and twenty
combinations printed `NEVER REACHED`.

**Broken on purpose, as always:** `--break` puts the original 4.20:1 defect
back from the browser side and **inverts the verdict**, so a sabotage run that
finds nothing is the failure. It found it: *1 distinct failing style, «11:42
PM»*. Restored, the run is `PASS — 56/56, canary failed as required`.
