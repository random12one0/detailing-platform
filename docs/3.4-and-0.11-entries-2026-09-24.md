## INSERT 3 — into ROADMAP 0.11

### THE GUARD R2 DOES NOT HAVE IS WRITTEN — 2026-09-24. Nothing else moved.

**`supabase/functions/_shared/photoKey.ts`, with
`tests/photo-key-isolation.test.mjs`. 61 assertions, credential-free, no dev
server.**

**WHAT IT REPLACES.** Postgres keeps one detailer out of another's photographs
with `(storage.foldername(name))[1] in (select public.current_business_ids()::text)`
on `storage.objects` — `20260906010000_job_photos.sql`, and the same shape on
`expense-receipts` and `business-media`. **R2 has no equivalent, because it has
no idea what a business is.** The move does not merely change where bytes live:
**it deletes a guard the database has enforced since 2026-08-27.** This is the
first of `docs/the-photo-allowance.md` § 4's *"two questions at that door"*:
**is this your business?** The second — *do you have room?* — is
`job_photo_budget()` and **is not built here.**

**AN ALLOWLIST, NOT A DENYLIST, and that is the whole design.** The two obvious
implementations are wrong:

```js
key.split("/")[0] === businessId      // WRONG
key.startsWith(businessId + "/")      // WRONG
```

**Both answer yes to `B/../A/booking/photo.jpg`**, whose first segment is `B` and
whose object is `A`'s. Every denylist for that — strip `..`, reject `%2f`,
normalise backslashes — is a list somebody has to keep complete, and its failure
is silent: the guard still returns `true`, nothing goes red, and the cross-tenant
checks pass on the day it is written.

**So nothing is stripped or normalised. A key is parsed against the ONE shape
`storagePath()` mints — `businessId/ownerId/id.ext`, three canonical lowercase
uuids — anchored at both ends, and anything else is not a key.** `..` is not a
uuid. `%2f` is not hex. A leading slash makes the first segment empty. **The
attack surface is not defended against; it is unrepresentable.**

**THE TEST CALLS THE MINTER RATHER THAN DESCRIBING IT.** It imports
`storagePath()` from `app/src/lib/photo-rules.js` and feeds its output to the
guard, so *"the guard accepts what we store"* is proved by running both. **Two
copies of a path rule that can disagree is this repo's most repeated failure**,
and the minter's own header warns about precisely that for its half.

**STRICTNESS WAS CHECKED, NOT ASSUMED.** A guard this narrow would refuse any
object stored under an older shape. Read against the live database (read-only,
`kguqylyzgyzfktkfnhjb`, confirmed before the query): **`job_photos` holds 0 rows,
0 bytes, 0 distinct paths**, and **no expense carries a receipt path.** There is
no legacy key to honour. **If that ever stops being true this file must be
widened deliberately, not loosened to make a run go green.**

**WHAT THE CHECK ASKS:** 4 minted keys through every `extForType` branch; **17
wrong-tenant keys** — A's own key handed to B, four traversal shapes, a
percent-encoded separator, backslashes, a leading slash, a bucket name glued on
the front, an absolute URL, a query string smuggling the other tenant, a null
byte, an uppercase uuid, a trailing space, a bare prefix, a wildcard, the empty
string; **10 bad callers** — `undefined`, `null`, `""`, `"*"`, a prefix of the
id, an array, an object, a trailing slash, an uppercased id, a SQL fragment; the
refusal message asserted to name **neither** the key nor the other tenant,
because a refusal that echoes it tells a prober the object exists and whose it
is; and **both naive guards run and asserted to be fooled** by the key the real
one refuses.

**BROKEN ON PURPOSE THREE WAYS:** the naive split swapped in — **5 red**,
including the assertion written to catch exactly that; **always-yes — 22 red**;
**always-no — 5 red**. Restored, **61/61**. A guard that cannot refuse and a
guard that refuses everything are both caught, in opposite directions, by
assertions that exist on every run.

**EXPLICITLY NOT DONE, and each is deliberate:**
* **no upload path switched** — no presigned-URL function, no R2 client, no
  bucket call;
* **`photo_total_gb` untouched at 1.** It goes to 10 **in the same change as the
  switch, never a commit earlier** — `docs/the-photo-allowance.md` § 2 — and that
  change is in `app/src`, which was another session's;
* **no photo written**, and `job_photos` still holds 0 rows;
* **no key read or printed.** Where the R2 credentials live is
  `docs/services-and-secrets.md`; their values were never queried, in full or as
  a prefix;
* the **budget** half of the door, and the **periodic reconcile** of § 6 —
  `businessPrefix()` exists for the reconcile to sum against, and the reconcile

**So 0.11's box stays `[ ]`.** The dangerous half is done and proved; the switch
