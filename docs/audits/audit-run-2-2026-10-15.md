## R2-04 — A wrong expense can never be fixed or deleted; the only way to add one is permanent.

- **Roadmap:** 101.1
- **Severity:** before
- **Category:** opportunity
- **Area:** Money
- **Found by:** looks auditor (claude-sonnet-5-5)
- **Second check:** confirmed by opus — The expense rows at app/src/screens/Money.jsx:999-1024 are plain divs with no onClick; the only button is the receipt thumbnail, which opens the receipt viewer. The only app write to the expenses table is the insert at app/src/components/ExpenseModal.jsx:124-131 (receipts.js only touches receipt fields), and Money.jsx:1063-1068 itself says the sheet 'is add-only ... there is no way to reopen a saved one'. No open ROADMAP item covers editing or deleting an expense; the closest open items are 97.29 (row cap) and 4.1 (job undo), and neither is about this.
- **Supposed to:** A detailer who typed $1,890 instead of $189 should be able to correct or remove the expense so profit is right.
- **What the code does:** The expense list rows are plain text (no tap action) and the only code that writes to the expenses table is the insert in ExpenseModal. The Money screen's own comment says the sheet is add-only. Receipts can be removed, the expense itself cannot.
- **What happens:** One slip of the thumb on a phone number pad permanently lowers 'Earned less expenses' and the accountant export for that month, and the detailer has no way to correct it short of contacting support.
- **Fix:** Make each expense row open the same sheet with the saved values, with Save changes and a ConfirmTap Delete.
- **Reproduce:** Money > Expenses > Add, save any amount, then try to tap the new row: nothing opens.
- **Impact:** Every detailer who logs expenses; wrong profit and wrong tax export with no fix.
- **Benefit:** Profit figures and the export can be corrected, which is the job this screen exists for.
- **Effort:** medium
- **Risk of fixing:** low
- **Confidence:** high
- **Evidence:**
  - file: `app/src/screens/Money.jsx:997-1028`
  - file: `app/src/components/ExpenseModal.jsx:120-131`

## R2-05 — The expense form accepts a negative amount, which would raise profit instead of lowering it.

- **Roadmap:** 101.2
- **Severity:** before
- **Category:** defect
- **Area:** Money
- **Found by:** looks auditor (claude-sonnet-5-5)
- **Second check:** confirmed by opus — ExpenseModal.jsx:201-209 is a type=number input with no min, and both the guard at :121 and the disabled check at :284 use !Number(amount), which lets -50 through; :129 inserts Number(amount) as is. The expenses.amount column at 20260827000200_tenant_data.sql:342 is 'numeric not null' with no check, and no later migration adds one. No open ROADMAP item covers it; 97.31 and 97.34 are about promo discounts and formatting.
- **Supposed to:** An expense is money that went out, so the amount should be more than zero.
- **What the code does:** The amount box is a number input with no minimum, and Save is enabled for any non-zero number, so -50 passes. The column is 'numeric not null' with no check that it is above zero.
- **What happens:** Pressing the minus key on a phone number pad (or a pasted -189) records a negative expense: 'Earned less expenses' goes up and the accountant file shows a positive line.
- **Fix:** Add min="0" and require Number(amount) > 0 in the Save check, and add a check (amount > 0) on the table.
- **Reproduce:** Money > Expenses > Add, type -50, pick a category: Save expense is enabled and saves.
- **Impact:** Anyone mistyping an amount; wrong profit and export. I did not check later migrations or server rules for a guard.
- **Benefit:** Stops a bad number reaching the profit figure.
- **Effort:** small
- **Risk of fixing:** low
- **Confidence:** medium
- **Evidence:**
  - file: `app/src/components/ExpenseModal.jsx:201-209`
  - file: `app/src/components/ExpenseModal.jsx:121`
  - file: `app/src/components/ExpenseModal.jsx:284-285`
  - file: `supabase/migrations/20260827000200_tenant_data.sql:342`

## R2-06 — On Promo codes, 'Code added' and error messages appear below the whole list, and failures to switch a code on or off are never shown.

- **Roadmap:** 101.3
- **Severity:** before
- **Category:** defect
- **Area:** Money
- **Found by:** looks auditor (claude-sonnet-5-5)
- **Second check:** confirmed by opus — Promos.jsx:308 draws the one shared msg box after the codes list (279-306), below both the Save sale (201) and Add code (271) buttons; addCode shows the raw Supabase error.message on failure (118), so a duplicate code shows Postgres's 'duplicate key value violates unique constraint' text. toggleCode (124-127) ignores the update's error and just reloads, and load (97-100) ignores its error too, so a failed load and having no codes both render nothing because of the codes.length > 0 check at 279. No open ROADMAP item covers this; the promo items 97.9, 97.23 and 97.31 are about pricing and booking.
- **Supposed to:** After pressing Save sale, Add code or Deactivate the detailer sees straight away whether it worked, in plain words.
- **What the code does:** One shared message is drawn at the very bottom of the screen, under the Your codes list (and the 390px screenshot shows the Save sale and Add code buttons are 400-700px above it). A duplicate code prints the database's own message, not a sentence. toggleCode awaits the update but ignores its error, and the list has no loading or 'no codes yet' state (a failed load looks the same as no codes).
- **What happens:** A detailer taps Add code, nothing visible changes where they are looking, so they tap again or give up; a duplicate code shows text like 'duplicate key value violates unique constraint'; a Deactivate that failed looks like it did nothing.
- **Fix:** Draw the message directly under the button that was pressed (two messages: sale and code), replace the duplicate error with 'You already have a code called X', check the error in toggleCode, and show a short 'No codes yet' line.
- **Reproduce:** At 390px open Settings > Promo codes, add the same code twice: the red box appears under the whole codes list, outside the first screen's view, and reads as a database error.
- **Impact:** Any detailer setting up promos on a phone.
- **Benefit:** Feedback is seen and understood; no more guessing whether a sale or code is live.
- **Effort:** small
- **Risk of fixing:** low
- **Confidence:** high
- **Evidence:**
  - file: `app/src/screens/more/Promos.jsx:118`
  - file: `app/src/screens/more/Promos.jsx:124-127`
  - file: `app/src/screens/more/Promos.jsx:279-306`
  - file: `app/src/screens/more/Promos.jsx:308`
